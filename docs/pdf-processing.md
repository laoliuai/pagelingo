# PDF 本机处理与静态阅读产物

状态：2026-10-12。用户明确优先阅读效果，可提供 GPU / 内存；第一部署方式为在当前机器处理 PDF，将完成产物送到服务器保存与阅读。本文调整 P0 之后的实施重点，不代表增强 parser、正式 Reader、服务器导入或翻译流水线已经实现。

## 处理与阅读分开

```mermaid
flowchart LR
  P[本机 PDF] --> A[结构解析]
  A --> I[Reader IR 与原文资产]
  I --> T[共享翻译 SDK]
  T --> R[结构化译文]
  I --> H[静态阅读快照]
  R --> H
  H --> U[校验并导入服务器]
  U --> W[网页阅读与下载]
```

本机承担模型推理、语义重建、翻译和 HTML 生成；阅读阶段不再调用 PDF parser，也不因为再次打开文档而请求翻译。处理配置与内容兼容时复用原件、解析与译文。服务器运行网站、PostgreSQL / ObjectStore 与后续助手 API，不需要为了展示已完成文档常驻解析模型。

第一条链路可以是本机 CLI 完成处理后导出、服务器导入。后续可改成服务器提交任务，本机 worker 通过受控接口领取和上传结果；任务协议与阶段产物仍然相同。GPU worker 不需要与 Web/API 同机，也不要求把 PostgreSQL 暴露给远程处理机。

## 质量优先的配置评测

现有 P0 配置为 MinerU 4.0.10 `basic` / CPU ONNX / TXT / image analysis。公式、表格与图像分析已经使用；它不是完整高质量配置的验收结果。

下一轮比较 `standard` 与 `advanced`：前者使用小模型与 VLM，后者使用同一部署增加推理计算；不将 GPU 本身当作质量开关。标题层级和跨页表格单元格的 LLM 辅助属于单独功能，应对相关样本单独评估。其服务凭据、用量与诊断独立管理，不静默调用翻译 Provider，也不写入产物。配置含义见 [官方 tiers](https://opendatalab.github.io/MinerU/usage/tiers/) 和 [模型配置](https://opendatalab.github.io/MinerU/usage/model_source/)。

当前机器：RTX 3070 / 8 GiB，47 GiB 系统内存；查询时 GPU 空闲约 2472 MiB。这是时点记录，不是处理任务可保证的预算。优先验证 llama.cpp 量化 VLM、CPU 小模型与适量 GPU offload；实际模型 revision、量化、GPU 层数、上下文 / 批量和最坏显存通过短样本冻结。显存充足后再比较 GPU 小模型 / 其他引擎，不能直接把现有 CPU 环境的设备变量改为 CUDA 并假定可运行。

选取两本书中的公式、图表、代码、跨页和提示框，以及 BERT 双栏的代表页，先做可读样本。不同配置使用相同渲染器，分别评价遗漏、公式、顺序与展示。效果稳定后再扩展正式 corpus / golden；耗时和资源作为部署约束记录，不优先用低资源配置否决效果更好的方案。

## 持久化三种数据

| 数据 | 用途 | 保存方式 |
| --- | --- | --- |
| 原件、raw、Reader IR 与资产 | 保留结构和来源，支持重新投影 / 重解析比较 | 不可变对象，独立 parse run |
| 译文与翻译运行 | 重译、缓存、质量改进和 SDK 复用 | 服务器 PostgreSQL 为导入后的业务依据；离线包带版本化译文快照 |
| 静态阅读快照 | 重复阅读、服务器快速展示与离线导出 | 不可变 HTML / 数据 / 资源包，由前两类生成 |

HTML 是可重建产物。仅改 renderer / CSS / 公式排版可重新渲染；更换翻译模型或术语策略复用解析并按缓存依赖重译；更换 parser / normalizer 则创建新的 parse run，不覆盖旧版本。快照依赖 parse run / IR hash、translation run / 内容 hash、renderer 与资源版本、输出选项，避免展示过期译文。

正式渲染策略应在共享 renderer 中实现，React 网站与批处理 / 静态导出复用它，消费共同 Reader IR；PDF 与未来 LaTeX 只需不同的输入适配。当前 P0 预览直接读取 MinerU raw，用于早期验证，不作为正式 renderer 的公共协议。后续助手从保存的原文 IR 投影读取上下文，不依赖运行机的 PDF parser 或渲染 DOM。

本机离线阶段使用文件对象、阶段 manifest 和检查点，不新建一套需要同步的业务数据库。导入时服务校验源 hash、schema / 版本、全部必需文件与 checksum，在 ObjectStore 写入成功后提交 PostgreSQL 引用。重复导入相同包应幂等；冲突不能覆盖已经保存的成功运行。原件、原文和译文仍可分别取回，服务器不会只剩一个无法重新生成的 HTML。

## 阅读包

```text
document-bundle/
  manifest.json
  source.pdf
  source-ir.json
  translated-ir.json
  index.html
  reader-data.json
  pages/ or chapters/       按页或有上限的阅读分片
  assets/                   图表、原页 / 区域、CSS、字体、脚本
  licenses/
```

以上是正式包的待冻结结构。所有必需资源使用可重绑的本地引用；导出 ZIP 保留目录，不能依赖运行机的绝对路径或外部 CDN。公式可预生成 HTML / MathML / SVG，或随包带完整数学运行时和字体。普通论文是否单页取决于实际排版负担，长书不能一次挂载所有正文和公式。章节用于目录，实际 DOM 由按页切换或有限的段落窗口控制；共享 CSS / 字体只保存一份，全部分片随包提供。

图、表主体默认从原 PDF 高清裁剪，保留文字、箭头、线条、颜色和单元格的原有外观；caption / footnote 单独保存和翻译。被误分类为表格的结构图也不重建 HTML 表格。结构化识别结果仍保留在 IR，供未来助手和可选结构化视图使用。区域图片内部暂不翻译或提供直接选字；定位可能有误，因此保留原页入口与裁剪诊断。此策略不依赖启动 VLM，增强解析的后续价值包括更准确的区域、顺序、正文及公式识别。

可导出原文、译文和对照视图。静态包提供阅读内容，后续助手、对话同步、重新翻译和任务恢复仍通过应用后端完成；LLM Key 不放进 HTML 或导出包。

## 当前展示问题与已做验证

`debug.html` 是 P0 的块 / 来源检查。它使用普通文本投影，不排版行内公式 / 表格，展开视觉子项，两栏不逐段同步。图片完整不代表该页面具有正式 Reader 的展示效果，也不能据此判定所有 parser 质量。

本轮将 LLM 全文检查页与资产复制到新目录，在断网 Chromium 打开：1005 个不同图片路径存在，首屏图片加载正常，无脚本错误 / 失败请求。只能证明工作区这份产物可移动，尚未检查用户下载后的具体目录。

已增加 [原文静态预览工具](../benchmarks/pdf/tools/README.md)：直接复用现有 MinerU raw 和图片，用上游语义 HTML renderer 与预排版公式生成可离线 ZIP。这是检验渲染层的试验，仍使用 basic CPU 的原始解析；没有重解析、翻译或实现正式 Reader IR。原始 P0 产物保持不变。

用户报告旧版整本单页偶发 hang，以及图 / 表重建失真后，P0 导出改为每个原 PDF 页一份 HTML，首页含目录，阅读页含翻页 / PDF 页码跳转；CSS 与字体共享，不在浏览器积累其他页的正文。所有 `image / chart / table` 主体改为原 PDF 216 dpi PNG，点击可放大，说明文字独立保留。包仍是原文渲染试验，原 raw / source / manifest 不改；旧版单页包保留供比较。

2026-10-10，根据 RL 书的强调框 / 算法背景和条件期望乱码反馈，导出再增加两层补充。原 PDF 中可确认的直接页面填充矩形 / 圆角框投影为 HTML 容器，保留浅色背景、边框和标题条，内部段落仍可选取，未来可翻译；图表的填色区域不当作正文强调框。当前投影不覆盖嵌套 Form、扫描背景、透明或倾斜路径，不能保证全部装饰都恢复。Reader IR 应保留容器与成员关系，不将有意义的 sidebar / aside 当页眉脚丢弃。

算法整体采用原件区域图，保留编号、缩进、连线、公式和浮动标题。普通 code 仍保留文本和空白。异常控制字符、未映射文字和无法确认的数学问号下标采用原件区域回退并显示提示；问号下标只表示需要确认，不能一概判为数学错误。遇到公式和普通段落被错误合并，P0 暂保留整个来源块，里面的正常 prose 也因此暂不能直接选取 / 翻译；正式 IR 需要识别来源区间后再拆分。

例如书内 49 页（PDF 第 50 页）的条件期望被 MinerU 分类为 text，包含 U+000C / U+0003。KaTeX 从未校验第一条式子，因此旧包的“公式排版失败 0”不能证明公式识别正确。新包显示原 PDF 区域，保留正确的条件符号和上下标；算法内另一个异常字符也通过原件图保留。所有处理复用已有解析、不调用模型、不改 raw / 原件 / 原 manifest，导航补充书内页码。最新 RL 包、实测与限制见 [预览工具](../benchmarks/pdf/tools/README.md)。
