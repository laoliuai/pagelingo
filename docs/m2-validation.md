- 浏览器慢流：响应持续 32 秒，间隔 16 秒，单次请求完成并报告用量；任务结束停止保活。
- 恢复期间正文新增/重排、标题/语言变化均拒绝旧任务，覆盖仅译文模式；worker 重启后沿用配置的 1 MiB 缓存预算。

## 限制与复现

固定 arXiv / GitHub / 文档 fixtures 验证结构行为，不代替真实站点语义评测。自动化运行 Playwright Chromium；只对临时测试副本预授予 fixture/API host 权限。生产 manifest 不含全站 host_permissions 或自动注入脚本。Chrome / Edge 原生 action、权限弹窗、深色模式和人工质量验收仍需按 [安装指南](install-m2.md) 操作。

M3 尚未实现术语应用、文档分析或人工语义评测；PDF / LaTeX 应用尚未实现。SDK 预算是通用估算，usage 取决于服务是否返回；拒绝/空译文/无效模型 JSON 等失败响应可能未计入全部 Token，统计可能偏低。后台意外中断后的重试可能产生额外计费；持久化降级时不保证恢复。

普通检查不读取 `.env.local`、不调用付费模型。完整回归：`npm run check`；真实联调：`npm run test:llm:extension`；构建安装包：`npm run package:extension`。

## 0.2.1：Edge 用户反馈的 X 页面显示问题

2026-10-06，用户在 Edge 打开 X 状态链接，连接测试通过，页面处理进度完成但未看到中英对照，也不清楚布局预览在哪里。直接访问该 [状态链接](https://x.com/goyal__pramod/status/2106244243727507733) 在本环境返回 403，无法检查用户登录后的实际 DOM。

旧提取器只识别 `p`、标题、列表等语义标签，并优先选择文本最多的 `article`。人工 X 样本复现了正文 `div` 被跳过、较长回复被误选的问题：普通帖子预期 1 块却处理 6 块回复；长文预期 6 块，却处理 3 块回复。预览使用同一个提取器，因此也会漏掉正文。这证实了代码缺口，尚未证实用户页面中的全部 74 块具体来自哪里。

修复内容：

- 按 X 状态 ID 和帖子自身的时间链接识别正文，排除引用帖；已加载的长文识别标题、Draft 段落和列表，代码块不送入模型。
- 提取和正文版本检查共用正文范围；点赞、作者区域和其他回复变化不清除译文，正文编辑、新增或重排仍使旧任务失效。其他网站单独使用 `primaryColumn` 标记时沿用通用提取。
- 中文插在原文节点之后，避开 X 的文本截断；不移动原节点，链接事件和精确恢复保留。标题译文保留字号、粗细和标题层级，颜色继续随页面主题变化。
- 面板明确说明预览在当前网页正文下方显示【布局预览】，不打开新窗口、不调用 API；进度标为段数，API 请求数单独显示。

适配标记参考 [X Translator 作者项目](https://github.com/Zhao73/x-translator) 和 [FluentRead 作者源码](https://greasyfork.org/en/scripts/482986-%E6%B5%81%E7%95%85%E9%98%85%E8%AF%BB/code)。测试页面为人工编写，没有复制用户登录页面或会话。

最终 `npm run check` 全部通过：108 项单元测试（SDK 66 / 扩展 42）、1 项独立 SDK 包消费和 29 项 Chromium 测试。新增 11 个 X 单元用例、3 个浏览器用例；验证当前帖选择、引用和其他长文回复干扰、未加载正文不发送回复、译文真实可见且位于截断区域外、预览零 API 请求、正文变化失效、互动更新保留译文、原节点与事件保留和恢复。

独立审查提出的三个重要范围选择问题均已通过 RED→GREEN 回归修复，标题呈现问题也已修复。任意 Draft 行内 CSS 样式不完全复刻到译文，作为后续适配项；语义标签的强调、链接与代码保护仍保留，原文样式不变。

X 当前采用保留原文方式，“仅译文”也保留原文；自动翻译滚动加载的新帖子尚未实现。此轮没有调用真实付费模型，SDK 仍为 0.2.0；真实登录 X / Edge 的人工复测仍需更新插件并刷新网页后进行，步骤见 [安装指南](install-m2.md)。

## 0.2.2：X 页面自动更新误中断及直接重试

2026-10-06，用户在同一篇 X 文章中看到前几段中英对照，但即使不滚动，任务也提示“正文已变化”并停止，停止按钮变灰且没有明确重试入口。本环境仍无法检查用户登录后的真实 Edge DOM。

旧版本直接比较原文 `outerHTML` 和节点身份，自动样式、追踪属性、通知标题以及相同正文节点被重建都可能触发失效。失效路径已取消任务并移除旧译文，因此停止按钮不可用；面板没有明确标示任务已停止，也没有把翻译按钮显示为重试。这些代码问题已在人工 X 样本中复现，不代表已确认用户页面的具体自动更新来源。

修复内容：

- 原文范围快照忽略布局、追踪元数据和扩展输出，候选变化再比较有序的编码输入及本地链接/代码/公式资产；保留文字、真实格式、顺序、段落数量和可见性检查。
- 相同正文的重建、移动、透明节点切分、零宽锚点和代码高亮更新会重新绑定已完成译文及待完成块，继续当前 SDK/后台任务，不增加翻译请求或重复计数；复制的扩展包装与译文也能清理。
- 初始分块提取期间，媒体加载文字变化不会妨碍稳定翻译输入的建立。X 通知标题不影响正文，发送到模型的文章标题只使用已过滤的正文块，隐藏或可编辑文字不进入标题上下文。
- 真实正文变化自动停止并显示原因；面板显示“已停止”和可直接点击的“重新翻译”，无需先恢复页面，有效缓存继续复用，新任务仍可停止。
- SVG/MathML 公式结构、文字/链接/代码实际修改、标题/语言变化和 CSS 隐藏正文仍会使旧译文失效。保留对正文以外 DOM 更新的检查，避免遗漏兄弟节点或 `:has` 等 CSS 对正文可见性的影响；快照相同时避免重复扫描各块样式。

最终 `npm run check` 全部通过：131 项单元测试（SDK 66 / 扩展 65）、1 项独立 SDK 包消费和 32 项 Chromium 测试。新增 23 个稳定性单元用例及 3 个浏览器用例。浏览器测试在不滚动时每 50 ms 更新布局、通知标题及媒体文字，确认全部段落完成且没有额外请求；替换相同原文并实际终止 worker 后仍完成 21 块且无重复译文；通过真实 popup 入口验证正文修改后的重试、停止、再次重试和缓存复用。

独立只读审查确认的初始提取抖动、节点切分、零宽锚点、译文位置、标题过滤、公式结构、CSS 可见性及待完成块回填问题均经 RED→GREEN 修复，最终无待处理的重要问题。复杂动态长页的样式扫描仍可后续做 Chromium 性能测量。

此轮没有调用付费模型，SDK 仍为 0.2.0。自动处理新增帖子未实现；真实登录 X / Edge 页面仍需用户按 [安装指南](install-m2.md) 更新扩展并刷新原页面后复测。
