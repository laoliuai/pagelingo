## 已验证的行为

- 生产 popup 的真实点击调用原生 `sidePanel.open`，浏览器运行上下文确认侧栏页面已创建；右键处理函数先同步打开侧栏，再异步读取文章。
- 添加多个引用不请求模型；侧栏尚未启动时，连续投递的引用不会互相覆盖。发送后原始代码缩进、换行和末尾换行保持完整，包括右键文本压缩空白的情况。
- 全文、部分正文、仅引用的输入协议与预算；英文函数名混在中文问题中的局部匹配。目录过大时先缩减目录，保证问题和引用优先。
- 小文章用全文，大文章显示片段范围；超预算全文或必需引用在摘要 / 回答请求前明确失败。
- 真实 Pi 生命周期下的 SSE、普通 JSON、Unicode 分片、服务用量、取消、读取超时和安全错误。请求没有翻译的 JSON 输出约束，不自动重试。
- 停止保存部分回答；重试不重复用户问题。关闭侧栏后恢复为中断，可继续重试。
- 按 URL 保存历史与草稿，导出不包含 API Key；数量及字节容量清理。超大单条记录保存失败后，原记录仍保留。
- 切换文章、同标签页导航、生成期间接入其他文章均不跨文章写入。多窗口生成锁与版本检查避免覆盖新消息；先前草稿保存失败不会阻止之后发送。
- 较早对话摘要落库并用于后续请求，原始消息完整保留；无效摘要边界及未完成回答不会作为已完成记忆使用。
- 中英对照或仅译文页面提取原文，排除 PageLingo 生成内容；无关大选区不会阻止读取正文。图片只提供文字描述或缺失提示。
- Markdown 不执行原始 HTML、脚本或危险链接，也不自动加载模型回复里的远程图片。
- 翻译、术语导入与后写覆盖、缓存、停止、X 自动更新、后台恢复及独立翻译包继续通过回归。

## 0.4.1：选区预览与问答目标修正

日期：2026-10-06。插件 0.4.1、助手 SDK 0.1.1；翻译 SDK 仍为 0.3.0。

- 卡片默认显示选中文字，按实际侧栏宽度最多三行，超出部分显示省略号；展开后查看完整选区和次要的来源信息。

## 0.4.2：独立选区问题、回车发送与标签页侧栏

日期：2026-10-07。插件 0.4.2、助手 SDK 0.2.0；翻译 SDK 仍为 0.3.0。

用户在 0.4.1 的长文章上只选择 22 字符的 `Reinforcement learning`，询问「这是什么意思？」时，模型仍逐句解释所在引言。此前只调整 JSON 字段顺序和提示词没有充分解决这一场景：选区、段落 ID 和大量正文仍在同一条用户消息中，背景容易被当成提问目标。

- 当前问题采用自然语言消息：完整选区与问题放在最后一条用户消息中，文章、来源元数据、摘要另放在前一条仅供参考的消息。历史问题使用同样格式；围栏根据引用内的反引号自动加长，代码缩进、换行和末尾换行保持原样。
- 来源段落标识为 `sourceBlockIds`，用于定位背景；当前问题中不混入这些 ID、来源标题或整个来源段落。系统明确要求先解释实际选区，当前问题优先于此前对话，并避免把背景引言称为选区。
- Enter 发送、Shift + Enter 换行，Ctrl / ⌘ + Enter 保持可用；组合输入及 keyCode 229 的候选确认不发送。
- 原生侧栏全局默认禁用，只给用户明确打开的标签页配置 `enabled: true` 与含 `tabId` 的路径，并同步调用 `open({ tabId })` 保留用户手势。实例只接受自己的引用投递和文章，读取文章始终使用绑定的标签页。
