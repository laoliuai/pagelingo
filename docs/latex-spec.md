# LaTeX / arXiv 源码翻译规格草案

状态：设计草案，尚未实现。PDF Reader 达标后进入 LaTeX 阶段，复用网站、翻译 / 助手 SDK 及可部署服务器的后端存储。本阶段不安装 TeX 环境、下载源码或创建另一套翻译引擎。

## 1. 产品边界

在同一个 `apps/web` 中增加 LaTeX 源码输入，复用 PDF Reader 的文档库、任务、章节导航、译文 / 对照 / 原文模式及原文按需展开。

文档、运行、任务、译文和对话沿用 PostgreSQL；源码归档、项目文件与转换资产沿用 ObjectStore。来源使用稳定文档 ID、项目 manifest 与 revision，不依赖本机路径或网站 hostname；原始归档和项目文件以版本化对象保存。

首版目标是“源码 → 可追溯的结构化文章 → 高质量中文 HTML 阅读”。翻译后的 `.tex` 工程下载与中文 PDF 重新编译是后续独立里程碑；不能把编译通过等同于语义翻译正确。

明确区分输入：已有 arXiv HTML 可使用浏览器插件；只有 PDF 时走 PDF 管线；提供 LaTeX 源码时走源码管线。不同来源保留独立版本与来源信息，不能仅凭标题或 arXiv ID 混用解析缓存。

## 2. 输入与项目识别

- 本地单个 `.tex` 或源码归档；需要保存被引用的 `.tex`、图像、参考文献及必要样式资源。
- 后续可提供“按指定 arXiv 版本导入源码”，记录 identifier、version、来源与内容 hash；不存在源码时明确提示，不能伪造源码转换成功。
- 识别主文件及 `input` / `include` 依赖图。多个合理入口时需要用户选择；检测循环、缺失资源、非预期编码和大小写路径差异。
- 解包前限制总展开大小、文件数、层数与单文件大小；拒绝路径穿越、外部符号链接。任务只访问自己的工作目录。
- 首版按已验收的文档类别 / 宏包集合支持；自定义宏、条件编译和复杂绘图列为挑战集，遇到无法解释的结构保留原文并报告位置。

归档 hash 用于保存原始输入；解析身份另记录包含主文件、所有相关文件内容和解析配置的项目 manifest，不能只 hash `main.tex`。

## 3. 处理链路

```text
源码项目 → 校验 / 入口 / 依赖图
        → LaTeX 转换器 / 语法适配器
        → ReaderDocument + 源码映射 + assets
        → 投影到 TranslationDocument
        → translation-core
        → 回填译文 → 共用 React Reader
```

不以正则删除全部命令后翻译剩余文本，也不把整份 `.tex` 交给模型重写。转换工具的 HTML / XML 属于解析结果，不能未经结构校验直接作为页面可执行 HTML。

L0 比较 LaTeXML 与可保留语法 / 位置信息的解析方案。LaTeXML 官方定位包含 LaTeX 到 XML / HTML / MathML 转换，适合作为候选；不预先承诺所有宏包、源位置或输出样式均兼容。[官方说明](https://math.nist.gov/~BMiller/LaTeXML/)

首版面向阅读，若转换器能可靠产出语义树但不能给出精确可编辑的源码区间，可以提供节点 / 文件级来源。未取得可靠可逆映射时，不开放译文写回 `.tex`。

## 4. 翻译与保护

| 内容 | 处理 |
| --- | --- |
| 标题、摘要、段落、图注、脚注 | 映射为 SDK 翻译块 |
| `textbf` / `emph` 等已识别格式 | 映射为嵌套 format，内部文字参与翻译 |
| 行内数学、代码、引用显示内容 | SDK protected 对象，本地还原 |
| 数学环境、标签键、引用键、URL、文件路径、宏定义 | 原样保留，不能让模型修改 |
| 图形、独立公式、复杂表格、参考文献 | Reader 中保留结构 / 原件；只翻译有可靠映射的自然语言部分 |
| 未识别命令 / 环境 / 宏参数 | 不猜测哪些参数可翻译；保留并标记降级 |

保护协议、提示词、术语、校验和缓存语义复用 `translation-core`。Parser 不重新实现槽位编码，也不在 Python 中复制翻译管线。源码中的命令样例、注释和文本是数据，不成为模型或系统的执行指令。

格式、数字、单位、引用顺序和论述限定词需独立质量评测。保护对象不变只能证明结构保留。

## 5. 来源、模型与缓存

使用 [monorepo.md](monorepo.md) 的 Reader IR。来源区分 PDF 与 LaTeX，不要求源码段落必须具有 PDF bbox。

源码引用可包含 `fileId`、`sourceHash`、半开字节区间 `[start, end)`、字符编码及便于展示的行列。遇到宏展开，记录展开节点与调用 / 定义位置的多对多关联，不能强行假设每段对应一段连续源码。

缓存分层：

- 原始归档 / 项目 manifest。
- 解析：项目 hash、主文件、解析器 / 版本、宏包绑定 / 配置、IR schema 与归一化版本。
- 翻译：复用 SDK 的实际内容、模型、endpoint、语言、生成配置、上下文、术语和保护 / 提示词版本。
- 编译（后续）：译后项目 hash、引擎、TeX 环境 / 字体 / 宏包版本、编译选项。

Reader 引用和源码区间不作为通用翻译缓存 key。即使 PDF 和源码中的自然语言相同，也只有保护内容、语义上下文和翻译依赖一致才可命中同一译文。

## 6. 后续源码导出 / 编译

L3 才增加可逆源码编辑。先在任务副本中确认原工程可编译；保留原始工程，修改仅限已识别的自然语言区间。转义 `%`、`&`、`_`、`#`、花括号等 TeX 特殊字符，保留格式与保护对象的原始 token。

中文引入可能需要调整编译引擎、字体与宏包；不能假设替换文字后原 pdfLaTeX 工程一定可编译。为受支持模板建立明确方案，其他模板继续提供 HTML 阅读。

转换和编译在受限 worker 中执行：无默认网络访问、禁止外部命令 / shell escape、限制文件访问与 CPU / 内存 / 时间。只关闭 shell escape 不能替代进程隔离。编译失败时保留已可用的 Reader 和具体日志位置，不覆写原工程或旧成功产物。

## 7. 阶段与验收

- **L0：样本与转换评测。** 主文件、多文件引用、宏、公式、图表、参考文献；确定实际支持范围、来源映射精度与资源预算。
- **L1：原文 Reader。** 输出版本化 Reader IR，原文、图片、公式和引用可读；未知内容有可追溯降级，不静默删除。
- **L2：SDK 翻译接入。** 共用网站四种适用视图 / 对照能力、按块原文展开、缓存、取消、部分失败与重译；没有原 PDF 的输入不伪造 PDF 视图。
- **L3：源码导出与编译（可选后续）。** 只对明确支持的模板验证往返、编译、引用完整性与中文字体；编译成功和人工翻译质量分别验收。

自动测试覆盖保留对象不变、嵌套格式、转义、源位置重绑、取消 / 崩溃恢复、路径限制与缓存失效。人工检查术语、否定、限定、数字、引用和跨句指代。L0 后再确定量化质量与性能门槛；本草案不是已完成的工具选型或能力声明。
