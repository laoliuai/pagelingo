# 插件 0.4.4 安装与浏览器测试

产物：`apps/extension/dist/`，或 `releases/pagelingo-0.4.4.zip`。ZIP 解压后直接得到含 `manifest.json` 的目录，不需要启动网站或后台服务。翻译 SDK 为 0.4.0，助手 SDK 为 0.2.0；新版增加译文背景高亮，包含颜色、下划线与提示框占位保护，保留之前的选区提问、回车发送、标签页独立侧栏和个人术语功能。

1. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
2. 开启开发者模式，点击“加载已解压的扩展程序”，选择 dist 或 ZIP 解压目录。
3. 打开 PageLingo 设置，填写 Base URL、API Key、Model，点击“授权并测试连接”。Base URL 是 API 根地址，例如 `https://api.deepseek.com/v1`，不要加 `/chat/completions`。
4. 安装包不会读取项目 `.env.local`，请在浏览器设置页填写连接信息。默认 JSON Object；DeepSeek 官方接口自动关闭思考。代理/其他服务按实际能力选择 JSON、思考与 SSE 选项。
5. 打开普通文章页，点击扩展图标，再点击“翻译当前页面”。关闭 popup 后任务继续。

个人术语表已生效：在设置页选择 JSON / CSV / TSV 文件，确认合并、选择术语适用领域、保存设置，然后重新翻译。后续导入或手工更新均以后写覆盖同键词条，完整说明见 [词表维护](glossary.md)。PDF、iframe 和浏览器内部页面不支持；可以先用选中内容翻译检查接口与文本效果。

## 已安装版本的更新

如果原来加载的是本项目的 `apps/extension/dist/`，重建后在 `edge://extensions` / `chrome://extensions` 找到 PageLingo，点击重新加载，再刷新已打开的文章页，并关闭、重新打开阅读助手。插件详情应显示 0.4.4，原有 API 设置保留。

如果原来加载的是 ZIP 解压目录，将新版 ZIP 的内容覆盖到原来的加载目录，再重新加载扩展、刷新文章页。同一路径更新可沿用现有设置。

0.4.4 保留译文中的背景高亮、下划线和局部颜色，并保护 PDF 导出 HTML 中的占位变量与答题线。
配合 LLM Foundations v11 阅读包使用，增加漏列表符号、组合图 / 子图说明布局和密集公式脚注保护。
密集公式脚注按原 PDF 图像保留，其中的正文暂不翻译；点击图片可查看高清原件区域。
已安装 0.4.4 时更换阅读包并刷新页面后重新翻译即可；原生 PDF 浏览器视图仍不支持直接翻译。
原文预览可直接打开本地 `index.html`；插件当前只支持 HTTP/HTTPS，不能直接翻译 `file://`。
要翻译阅读包，在解压后的目录运行以下命令，再在同一台机器的浏览器打开
`http://127.0.0.1:8765/index.html`，进入所需 PDF 页并点击“翻译当前页面”：

```bash
python -m http.server 8765 --bind 127.0.0.1
```

这只提供静态文件，不运行解析器、数据库或 PDF 后端。也可把整个阅读包放到现有 HTTP
静态服务器，保留 `pages/`、`assets/` 和 `source.pdf` 的相对路径；处理一次后可反复使用。
旧页面若已有译文，先恢复页面或刷新后重新翻译，重新提取新的格式绑定；无需清空全部缓存。

## 阅读助手

文章空白处右键「PageLingo：打开阅读助手」；选择文字或代码后右键「PageLingo：添加到对话」。也可以从扩展面板点击「打开阅读助手」。引用先进入侧栏草稿，补充问题并发送后才请求模型。

Enter 发送，Shift + Enter 换行，中文输入法确认候选词不会发送。侧栏只属于打开它的标签页；切换到未打开助手的标签页会隐藏，返回原标签页恢复。新文章可单独右键打开助手，其选区和当前文章不会混入其他标签页。

默认复用现有连接，支持按 URL 保存历史、流式回答、停止 / 重试和长对话摘要。侧栏位置由浏览器设置控制，建议设为右侧。完整用法和验收步骤见 [阅读助手指南](assistant.md)。

## X 与布局预览

X 状态链接只翻译当前帖子或已打开的长文正文，忽略导航、推荐和回复。帖子译文放在原文下方，避开文本截断区域。点赞和回复变化不清除正文译文，正文编辑或切换帖子时旧任务失效。请等待正文加载完成后再处理；未找到当前正文时会提示重试，不发送其他回复。

无需滚动也可能出现页面自动更新。0.2.2 允许样式、追踪属性、通知标题和媒体状态更新；网站重建相同正文节点时，已完成译文会重新绑定并继续翻译。原文文字、链接、代码、公式、段落数量/顺序或可见性变化时，任务自动停止并说明原因，面板出现“重新翻译”，直接点击即可处理最新正文。有效缓存继续复用，无需先点击“恢复页面”。“已停止”按钮变灰表示没有正在执行的任务；新任务运行期间“停止”可用。

X 采用保留原文的显示方式，以免移动页面自身管理的节点影响交互；“仅译文”仍保留原文。“原文”隐藏中文，“中英对照”显示中文。自动处理滚动后新加载的帖子尚未实现。

“预览页面布局”在当前网页正文下方插入【布局预览】文本，不会打开单独的预览窗口，也不调用 LLM。选择中英对照后，关闭扩展面板即可在原页面查看。面板中的 `完成 / 总计 段` 是正文分块数量；实际 API 请求数单独展示。

## 建议验收顺序

- 在技术文档、GitHub README、arXiv HTML 各选择一页；检查代码、公式、列表、表格、标题锚点和深色模式。
- 切换中英对照、仅译文、原文，再恢复页面；复杂公式段落会保留原文。
- 同页再次翻译，查看缓存命中和请求数；缓存完整时无需新 API 请求。
- 翻译长页期间关闭 popup、停止、刷新或切换文章；停止后已完成译文保留，迟到结果不写入新页面。
- 在 X 长文保持页面不滚动，确认可完成翻译；真实正文更新后查看停止原因，直接重新翻译，检查停止按钮与缓存命中。
- 扩展管理页打开 service worker 的检查窗口，翻译期间停止 worker，回到文章确认接续且无重复译文。整个浏览器/页面重启后，需要再次点击翻译。
- 打开三个文章标签页并发翻译，检查进度、响应及错误；设置页可分别清理译文、文档、全部缓存。
- 导入词表并保存，搜索并编辑一条，再次导入同键新译法；确认保存后标题与正文采用相同规则，相关段落重新请求、无关段落命中缓存。

默认输入估算 6000 / 输出 4096 / 上下文 32768 Tokens，每批最多四个分片，跨标签页每 endpoint 最多两个请求。首次加最多两次重试；首响应/读取空闲 25 秒，总时限 120 秒。超大保护对象或最小分片仍截断时保留原文，并提示调整预算。

译文缓存默认 64 MiB / 30 天，同时受浏览器配额限制。清理全部缓存也删除结束任务记录；正在执行或暂停的恢复检查点保留，后续结果可能继续写入缓存。配额不足会显示临时内存降级；此时关闭后台可能丢失未持久化结果。

开发重建后，在扩展管理页点击重新加载，并刷新已经注入脚本的文章页。网络中断后的重试和客户端取消可能仍产生服务端费用。
