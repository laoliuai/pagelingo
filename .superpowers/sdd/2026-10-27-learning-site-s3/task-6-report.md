# S3 Task 6 — private Web capture and Reader APIs

Implementation base: `2857392c94ed19b8a00651cb3b7313b2a29afd60`; controller documentation commit `bfe9add` records approved R15. No model calls, historical backlog enqueue, original/legacy mutation, merge, or push.

## Architecture and exact interfaces

- `createWebCapturesService({ db, store, config, onPublication? })` exposes `create(principal, CreateWebCaptureRequest, idempotencyKey)`, `status(principal,id)`, `receiveFile(principal,id,fileId,body,mediaType,signal?)`, `commit(principal,id)`, and `cancel(principal,id)`.
- Registered routes: `POST /api/v1/captures`; `GET /api/v1/captures/:id`; `PUT /api/v1/captures/:id/files/:fileId`; `POST /api/v1/captures/:id/{commit,cancel}`. The transport ID is the server ingestion UUID; `captureId` remains the client's stable UUID, equal to the required `Idempotency-Key`. Canonical strict request hashing includes manifest, target and intent. Same owner/key/input returns the same durable ingestion/result; different input returns 409.
- Files stream to private exclusive random `web-staging` paths, never client paths. Per-file DB upload token/expiry prevents concurrent replacement. Every PUT, including an already-received retry, checks actual length and SHA and checks declared Content-Type. Interrupted attempts stay missing; only fully verified files acquire durable staging references. Upload timeout is the configured capture request timeout (default 20 seconds).
- `validateCaptureInWorker(input,signal,deadlineMs=60000)` runs Node sanitize/resource replay, bounded image framing/dimensions, UTF-8 validation, content fingerprint, preview generation, final manifest hashing, projection and real renderer/SDK replay in a terminable worker. Only uploaded paths/public limits/optional retained manifest+IR bytes enter the worker; environment is LANG/TZ only, no DB/actor/provider/master key. Heavy work is outside DB transactions. Cancellation/revocation is polled at 500 ms and the worker is terminated and awaited. No Readability second pass, external resource fetch, or model call.
- `PAGELINGO_CAPTURE_LIMITS_JSON` may tighten the existing strict `CaptureLimits`; the default budgets remain frozen. `RuntimeConfig.captureLimits` is the parsed result.
- Originals are preserved as immutable registered objects under internal `uploaded:<asset UUID>` source-file IDs. The authoritative manifest points to the server-cleaned complete scoped HTML and generated bounded previews. Uploaded previews/format trees are never accepted as authoritative. Missing/invalid images become explicit missing resources; undeclared hotlinks become unavailable, with readable original publication retained.

## Imported translation provenance (R15)

- Contracts export `WebModelTranslation`, `webModelTranslationShapeSchema`, `webModelTranslationSchema` with the unchanged `web-reader-translation/1` model shape; `WebImportedTranslation`, `webImportedTranslationShapeSchema`, `webImportedTranslationSchema` with `web-imported-translation/1`; and `WebTranslation` / `webTranslationSchema` / `webTranslationShapeSchema` as their union. `webGenerationKindSchema` adds `import` only to Web. PDF shapes/enums stay unchanged. Portable JSON schemas are synchronized, including a dedicated imported schema.
- Imported artifacts have `id`, `generationKind:'import'`, actual `sourceSha256`, `parseId`, `readerIrSha256`, `sourceSnapshotSha256`, `sourceContentFingerprint`, SDK/prompt/protection versions, source/target language, `status:'partial'|'completed'`, and accepted `blocks`. Each block contains `blockId` plus the R6 `nodeId`, `sourceTextSha256`, `source:TranslationBlock`, `rawText` proof. No job/profile/budget/provider/glossary/usage metrics are invented.
- The adapter matches a unique authoritative source block by node, hashes UTF-8 `naturalText` without whitespace normalization, compares canonical original structure (only the top-level SDK block ID may be rebound to the server ID), verifies supported versions, and reruns public `encodeBlock` / `validateStructure` / `decodeTranslation`. Inline/protected identities/content must match exactly. Persisted proof uses the server block ID; uploaded candidate bytes remain immutable evidence. Renderer replay compares authoritative source and validates/decode markers again. Invalid/unsupported candidates warn and are skipped; any valid accepted blocks become a real imported artifact. Before accepting a block, the adapter measures the UTF-8 serialized authoritative source + SDK-decoded translation entry against the configured oversized Reader-block ceiling. An over-budget imported result is skipped without truncation, while other valid candidates remain publishable.
- New source imports bind the actual serialized IR bytes being stored. Same-content later imports are rebased outside locks against integrity-checked retained manifest and exact retained IR bytes, creating a new Reader/import artifact on the existing source/parse. Final publication compares retained parse IR SHA. If a concurrent publisher creates that source after preparation, commit returns `409 CAPTURE_REBASE_REQUIRED`; retry the same ingestion commit to rebase, without dropping the candidate or inventing a new source.
- Migration 006 adds `generation_kind` and makes `web_translation_runs.job_id` nullable only for import. Model rows still require jobs; independent owner/document/source/parse/asset FKs remain effective when the job FK is null. All artifact update-rejection triggers remain.

## Publication, current versions and hooks

- Objects are written immutably before references. Final lock order is user → device/session → capture → document → existing `(204716,2)` publication/cleanup lock. Identity, authVersion, capture epoch/status, stored object availability/size and retained dependencies are rechecked; final principal expiry/cancellation is checked before transaction return. Missing objects roll back all references.
- URL normalization removes only the frozen tracking fields; canonical candidates do not merge sources. Dedupe stays within owner, normalized URL, document and scope kind/content fingerprint. Same content reuses the source and records a new capture event; changed content gets a new immutable source. PDF and link-only targets are rejected.
- A late/duplicate capture does not roll current backward. Complete/partial translation ranks cannot be replaced by pending/empty output. Complete source coverage cannot be replaced by partial capture coverage. Empty semantic captures cannot replace a useful current Reader; empty historical originals remain readable/downloadable with a warning, and an empty current source does not block a later useful source. New unpromoted sources and Readers remain available explicitly by version. Latest-source and current source/Reader pointers stay separate and consistent.
- `CapturePublicationHook = (client: PoolClient, event: CapturePublicationEvent) => Promise<string|null>` is optional. Event fields: `ownerId`, `authVersion`, `ingestionId`, client `captureId`, `documentId`, `sourceVersionId`, `readerVersionId`, `translationIntent`. It runs only during the first successful final publication transaction, after artifacts are registered, and must do only short durable scheduling work. A returned real job ID is persisted and checked by the existing exact-identity FK/trigger. The future adapter must enforce preferences, language, current provider/glossary revisions and input dedupe itself. No hook is installed by `createApp`; source-only/no-Key/Chinese behavior works now and creates no job. Tasks 9–11 can wire the hook explicitly; ordinary reads never enqueue work.

## Private reading and library dispatch

- `createWebReadersService({db,store})` exposes `descriptor`, `versions`, `chunk`, `image`, `manifest`, `file`, `progress`, `updateProgress`. Routes are the frozen `/documents/:id/web-reader`, `/web-reader/versions`, `/web-reader/versions/:versionId/chunks/:chunkId`, `/web-reader/versions/:versionId/assets/:assetId`, `/web-snapshots/:sourceVersionId/manifest`, `/web-snapshots/:sourceVersionId/files/:fileId`, and GET/PUT `/web-progress`. Descriptor/progress accept optional `versionId`; version lists accept page/pageSize. All are session-only, owner/document/version scoped and no-store.
- `assetMap` remains local resource ID → registered asset UUID; the asset endpoint accepts that UUID, never a storage key. `findWebReaderAsset` retains its existing local-ID behavior; its optional final `byAsset` boolean enables UUID lookup. Only registered image MIME types are delivered inline. HTML/CSS/JSON/raw original files use attachment, application/octet-stream and nosniff; archived CSS is never executed.
- Immutable byte/hash/schema validation reads happen outside user locks; a fresh session check precedes delivery. Descriptor snapshots are the server-generated manifest index. Raw HTML and preview HTML both download as attachments, for the later isolated client preview adapter.
- `webReaderDescriptorSchema` now preserves every own asset-map key after strict per-key/value validation and enforces 256 entries; portable `webReaderDescriptorShapeSchema` includes matching maxProperties. `Object.fromEntries` preserves `__proto__`, `constructor`, and `toString` as data without unsafe assignment. No general record-schema refactor.
- Progress validates source/parse/version/block membership and document CAS. Conflicts return 409 without overwriting. History positions remain stored. Version restoration uses retained same-source IDs or a unique quote+prefix+suffix match, otherwise explicit source-start hint; restoration itself makes no writes.
- Mixed library/get/count/search/pagination use the public PDF|Web union. Pending originals use awaiting-config only when a non-sensitive boolean provider-configuration presence query is false; configured pending originals are reader-ready without decrypting keys or scheduling work. Existing PDF repository guards, original source/asset routes, PDF Range behavior and PDF Reader paths remain PDF-only.

## Cleanup and recovery

- Every published original, source manifest, IR, translation, index, chunk and image is an `assets` reference, including all history. Existing orphan cleanup therefore protects all of them under the shared publication lock. Unreferenced objects wait at least 24 hours.
- Web staging cleanup first acquires user→capture locks to fence attempts untouched for 24 hours, clear their received/staging references and make files missing again. It then removes old orphan staging paths under the publication lock, retaining active attempts. Completed statuses do not depend on temporary staging and remain retrievable after cleanup.

## R16 follow-up — imported table-context overflow

Controller approval is recorded in `faac42f`; the initial task implementation is `2d9cb90d7cc305b5835ea6291c83a63486218f97`, and the task review base remains unchanged. Per-block preflight alone was insufficient: an independently valid 300 KB translated column header fits the single-block ceiling but is repeated with a body cell under the smaller multi-block ceiling. The ordinary renderer correctly rejected this; capture validation incorrectly rejected the whole original.

The renderer now additionally exports `buildWebImportedReader(ir: WebReaderIR, imported: WebImportedTranslation): WebImportedReaderBuild`, where `WebImportedReaderBuild = { build: WebReaderBuild; translation: WebImportedTranslation | null; rejectedBlockIds: string[] }`. It uses the same private planner as the unchanged public `buildWebReader`, with a diagnostic mode that collects translated proof IDs only from actual minimal one-primary source/context closures exceeding the byte budget. It removes all implicated proofs, preserves unrelated proofs verbatim, recomputes partial/completed status, and performs one normal complete build. If every proof is removed, the artifact is null and normal original-only status applies. Rejected IDs follow input proof order. Diagnostic incomplete chunks never escape. The algorithm performs at most two whole planning/SDK replay passes regardless of candidate count; no per-candidate full rebuild loop, truncation, fake completion, or budget increase is used.

Limits are the renderer's **existing fixed constraints**, not new configuration: 128 blocks, 256 KiB serialized multi-block chunks, 512 KiB for a single block. Structural/graph/context-count errors are not recovered; inherently unrepresentable source-only byte closures still fail the final ordinary builder. Both fresh and retained-source worker paths use the helper and append `Translation candidate exceeds Reader source/context budget: <blockId>` warnings, persist only its surviving artifact, and retain the original source/IR byte hashes. No publication/job hooks, PDF behavior, compatibility payloads, or HTTP API changed. The generated renderer catalog hash changed with its implementation.
